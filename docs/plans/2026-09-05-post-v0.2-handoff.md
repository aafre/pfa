# Post-v0.2 handoff — remaining major issues

Written 2026-09-05, after tagging `v0.2.0`. The quality gate is green
(`ruff check`, `ruff format --check`, `mypy src`, `pytest` — 151 passed).

Fixed in v0.2 (context for what's already done):

- Dashboard landed on the empty current month; only ever loaded one month, so
  every "vs last month" delta was a month vs itself (£0.00) and the 3-month
  cashflow chart had two empty bars. Now lands on the latest month with data,
  loads the prior two months, and has a currency switcher.
- Committed rows that deterministic rules can't classify were a dead end.
  Added `GET /categories` + `PATCH /transactions/{id}` (shared
  `pfa.services.corrections.correct_transaction` with the CLI) and an in-line
  category dropdown in the Activity Ledger.
- `amount_sign` guard had holes: an all-positive generic statement could commit
  booked as income once an account was assigned, and no-adapter batches skipped
  the check. Now required for every generic all-positive batch, surfaced in the
  preview (`GENERIC_SIGN_CONFIRMATION_REQUIRED`).

## Still open, ranked by user impact

### 1. Real-bank PDF extraction has never produced a clean import

Biggest gap. `docs/plans/2026-08-29-real-statement-extraction-findings.md` has the
detail. Synthetic fixtures pass; no real HSBC / AMEX PDF imports end to end.
Known failure modes in real layouts:

- A banner containing `Date` is accepted as a one-column transaction header.
- Header matching is too exact for currency-prefixed / suffixed / space-less labels.
- Once a header is found, non-transaction lines become candidates with no
  date/amount plausibility gate.
- Multi-line headers are not merged.
- `21 Jul 25` and year-less `Jul31` dates are unsupported / need statement-period
  inference.
- `CR` credit markers (including own-line) not fully handled.
- Continuation-line heuristics absorb unrelated nearby text.
- Headerless CSV exports are rejected rather than recognised with a positional
  warning.

Work item: add a real fixture per observed layout (`tests/fixtures/`), then a
date/amount plausibility gate in `src/pfa/ingestion/extractors/pdf.py`
(`_merge_continuations` and the header scan). Do not claim broad PDF support until
these journeys pass.

### 2. `GET /transactions` loads the whole table every call

`src/pfa/api/app.py` `transactions()` does `services.uow.transactions.all()` then
filters in Python — hit on every month switch, ledger view, and the chat facts
panel. Fine at ~400 rows, linear from there. Add a date-bounded query to
`TransactionRepository` (`src/pfa/db/repositories.py`) and a `since`/`month`
`WHERE` clause. `resolveInitialMonth` / `bootstrapDashboard` in
`src/pfa/web/app.js` also pull `?limit=500` just to find the latest month — a
`GET /transactions/months` (distinct `strftime('%Y-%m')`) would replace it.

### 3. Extraction timeout does not cancel the parser

`src/pfa/ingestion/batches.py` `_run_extraction` — on `TimeoutError` the staged
file is cleaned up only when the worker eventually finishes; a slow
`pdfplumber` / Tesseract run keeps consuming CPU. Single-user localhost, so
low urgency. A real fix needs a cancellable subprocess (not a thread).

### 4. Import-time categorisation only runs rules, never the model

`commit_batch` builds `ImportService(uow)` with no classifier
(`src/pfa/ingestion/batches.py`), while `/imports/preview` passes
`LocalTransactionClassifier`. Preview categories do carry through to commit, so
this is not a correctness bug — but a row the model *could* have categorised at
preview time (if the user committed before preview finished, or Ollama was down
then up) stays unresolved. Decide: reuse preview categories only (current), or
also run a deterministic re-pass at commit.

### 5. Minor / cosmetic

- `src/pfa/web/index.html` still has static "zero hallucination" copy in the Ask
  PAF intro card (the JS facts panel line was softened in v0.2).
- Categories page says "No category spending recorded" when a month has spending
  but every row is uncategorised — technically true, reads as a contradiction
  against the Overview total. Better copy: "₹X spent, none categorised yet."
- `evals/classifier.py` is a 4-case smoke test, not an accuracy benchmark. A
  representative residual-case dataset + grounded-answer eval are still required
  before any model-quality claim.
- Provenance shows `UNKNOWN` for imported-but-unclassified rows; consider an
  `import` label instead.
